# BBMarkAssistant · BB 作业批改助手

简体中文 | [English](README.en.md)

面向 Windows 的 Blackboard 作业批改桌面应用。通过 **pyustc** 登录中国科学技术大学统一身份认证，印刷内容使用 **MinerU OCR**、纯文本直接读取，手写或混合内容交给视觉模型读取原图。按教师提供的 **system prompt**，分别调用 **GPT** 或 **DeepSeek** 生成建议分数和简短评语。两份结果独立保留，教师选择、修改并逐份审核后，才提交到 BB 并回读核验。

## 核心工作流

```text
pyustc 统一身份认证 → Blackboard 同步课程、学生与作业
                              ↓
                    下载每名学生的最新提交
                              ↓
             自动判别：印刷内容 OCR，手写/混合内容保留原图
                              ↓
         教师评分标准 + 参考答案 + 满分 → system prompt
                  OCR 正文 / 原图 → 学生答案输入
                              ↓
            GPT 评分 / DS 评分 → 各自的分数、评语、依据与疑点
                              ↓
                  人工检查、修改并确认审核
                              ↓
                  提交 BB → 回读分数和评语
```

1. **接入 BB**：使用 `pyustc` 完成 CAS 登录，同步当前课程的学号—姓名名单、作业和提交记录。
2. **下载与 OCR**：每名学生默认取最新一次尝试，下载附件；选择本地 MinerU 命令或 OCR API，将正文、公式和图片内容整理成文本。
3. **按教师规则评分**：满分（默认 **10**）、评分标准和参考答案进入 system prompt；学生 OCR 内容或原图作为独立输入。可以单独调用 GPT、DS，也可以使用 DS 初评、GPT 复核的协作流程，返回建议分数、简短评语、评分依据和待检查项。
4. **人工审核**：对照原附件、OCR 和评分依据，修改最终分数及评语，逐份确认。**最终评语可以为空**。
5. **提交最终结果**：预览审核名单后上传。应用再次核对最新尝试、课程与满分，逐份提交并回读确认。

评分 API 的输出是建议值，只有人工审核后的结果可以回传。

## 快速开始

需要 Windows、[Git](https://git-scm.com/) 和 [uv](https://docs.astral.sh/uv/)。启动脚本会安装项目内的 Python 3.12 与应用依赖。

```powershell
git clone https://github.com/ly382965/BBMarkAssistant.git
cd BBMarkAssistant

# 使用虚构数据体验界面，不连接 BB，也不上传成绩
.\run.ps1 --demo

# 正常启动
.\run.ps1
```

也可以单独指定课程数据目录：

```powershell
.\run.ps1 --data-dir D:/BBData/course-a
```

每个数据目录绑定一个 BB 站点和课程。切换课程时使用不同目录。

## 首次配置与使用

1. 在“连接与设置”粘贴自己的 **BB 课程 URL**。仓库默认地址只是示例，不能代替实际课程地址。
2. 填写统一认证账号。密码可在界面输入；密码框留空时读取环境变量 **`USTC_CAS_PWD`**。手填密码优先，应用不将密码保存到配置文件；修改环境变量后重新启动应用。
3. 配置 MinerU、GPT 和/或 DeepSeek。两套评分服务的地址、模型、协议、API Key、超时等分别配置；API Key 可选择保存在 Windows 凭据管理器。
4. 登录后选择作业并“同步提交”，到“评分标准”填写满分、评分规则和参考答案。
5. 使用“① 下载”“② 识别 / OCR”“GPT 评分”或“DS 评分”；“DS 初评 → GPT 复核”会运行协作评分。“一键处理（DS）”会下载并准备输入后调用 DS。也可以直接点击评分，自动准备尚缺的附件和识别结果。
6. 检查每份作业，修改最终分数和可选评语，点击“确认此份审核”。
7. 点击“预览并上传已审核成绩”，核对名单、提交版本和最终结果后提交。

当前负责学生范围为 `PB23*`、`PB24*`，以及 `PB25000001`–`PB25000262`（含两端），并要求完整的标准学号格式。完整课程名单仍可查看。这是本项目的默认规则；用于其他班级时，请修改 [storage.py](src/bb_assistant/storage.py) 的 `is_in_scope()`，并同步界面中的范围说明。

## 自动分流与双模型评分

默认“自动”路线先由本次选择的评分服务查看页面预览，逐页判断印刷、手写、混合或无法确定。全部为印刷内容的附件使用本地或 API OCR，评分时只发送提取文字；包含手写、混合内容或无法确定的附件保留全部页面，直接发送原图评分。纯文本无需视觉分类。DOCX 保留原生文字、表格、公式和内嵌图片；图片按同样规则分流。

首次类型判别仍消耗少量视觉请求，结果按原件和配置缓存。切换 GPT/DS 时各自判别，但复用同一份有效 OCR；修改评分 prompt 不会重复运行 OCR。原件变化会使相关缓存失效。类型判别可能出错，可在“连接与设置”切换“全部 OCR”或“全部原图”；混合附件不会只识别其中一部分。单独点击“② 识别 / OCR”的自动分类使用 DS。

工作台分别显示 GPT 分、DS 分及当前采用的建议。两套依据和评分规则快照分别保留；通过“审核采用”和“采用此结果”选择建议，再编辑最终分数、评语并确认审核。程序不会平均两套分数，也不会把两者一致当作人工审核。

- **GPT**：默认模型 `gpt-5.6-sol`，协议 `responses`，服务地址可配置。支持兼容网关的非敏感 `gpt.http_headers`；不把密钥写入高级 JSON。
- **DS**：新配置默认 `deepseek-flash`，协议 `chat`。图片输入需要支持视觉的模型；旧设置保留原值，使用旧模型名时请显式确认或改为 `deepseek-flash`。
- 密钥可以分别设置为 `BBMARK_GPT_API_KEY`、`BBMARK_DEEPSEEK_API_KEY` 环境变量，优先于对应凭据管理器条目。应用不会自动拿 Codex 的密钥，也不会把环境变量复制到配置 JSON。设置环境变量后重启应用。
- 每个按钮每次都会重新请求对应模型，使用当前作业的规则。失败时清除该模型的过期建议，保留另一模型的成功结果供比较；采用旧规则的结果时界面会提示。

## DS Actor + GPT Critic

点击“**DS 初评 → GPT 复核**”启动协作评分，将 **DS 作为 Actor（初评与修订）**，**GPT 作为 Critic（按原件核查）**。这是一次评分中的模型复核循环，不训练模型，也不进行强化学习。在“协作复核”页查看逐轮记录，通过“协作结果”选择待审核的建议。

1. DS 根据当前评分规则及已准备的正文／原图，生成逐题判断、建议分数和依据。
2. GPT 阅读同一份作业、教师规则和 DS 的判断，逐题检查是否误读、漏判、误扣，给出可核查的原文证据及修订意见。即使总分相同，也会检查小问判断。
3. 如需修订，DS 重新对照作业和 GPT 的意见修改；GPT 再次复核。DS 不应无条件接受没有原文依据的意见。
4. 保存 DS 初评、每轮修订及 GPT 复核记录，供教师查看；最终仍须人工确认分数和评语。

高级设置 `actor_critic.max_revisions` 控制 DS 最多修订次数，默认 `1`，允许 `0`–`2`。`0` 表示只初评和复核，不自动修订。完成一次修订会增加一次 DS 和一次 GPT 请求；识别缓存仍可复用。

协作建议单独保留，不覆盖独立的 GPT／DS 建议。结果标记为 `accepted`（GPT 复核通过）、`needs_human`（达到次数上限仍有分歧或需要人工判断）或 `incomplete`（调用失败、响应不完整等）。**复核通过不等于答案正确，也不等于人工审核**。未完成的流程不能作为完整协作评分采用；剩余分歧保留给教师检查，不会自动上传或审批成绩。

## MinerU：本地或 API

### 本地命令模式

在项目目录运行：

```powershell
.\setup_mineru.ps1

# 可选：指定模型来源或自定义数据目录
.\setup_mineru.ps1 -ModelSource huggingface -AppData D:/BBData/course-a
```

脚本创建独立的 `.mineru-venv/`，下载并验证 Standard 模型，将模型与缓存放在 `.mineru/`，然后配置应用的本地命令绝对路径，默认使用 **Advanced** 解析。Advanced 共用 Standard 模型，但增加推理计算；DOCX 按 MinerU 的格式限制使用 Flash 提取结构，再识别内嵌图片。安装和模型下载需要网络；应用与源码仓库不捆绑模型。

默认安装器会配置项目 `data/` 和 `%LOCALAPPDATA%/BBMarkAssistant`；传入 `-AppData` 时只配置指定目录。安装完成后重启应用，必要时点击“使用已安装的本地 MinerU”。

已有本地安装可点击“使用已安装的本地 MinerU”并保存，将命令切换为 `--tier advanced`；自定义命令不会被自动覆盖。若要重新识别已有 OCR，勾选“本次重新识别已有结果”后执行 OCR，避免继续使用旧缓存。

“OCR 调用方式”的 `command / http / mineru_v1` 与识别档位是两个设置。本地使用 `command`，在“本地 PDF / 图片识别档位”选择 Advanced，再保存连接设置。支持识别的 MinerU 4 命令会自动同步参数，其他自定义命令保持原样。

扫描件或混合 PDF 可将“本地 PDF 文字识别方式”改为强制视觉识别（`ocr`），避免沿用错误的文字层；清晰的电子文档可以保留自动模式。可选的“扫描 / 手写 PDF 补识别（较慢）”用本地模型对 300 DPI 页面增加整块转写，保留主 OCR 和原页码。辅助转写可能漏字或与主结果冲突，不能视为纠正后的答案；缺失和冲突需对照原件审核。这项功能增加处理时间，仅支持本软件安装的本地 MinerU。

本地 OCR 直接调用命令，无需启动 HTTP 服务。自定义命令使用 JSON 参数数组，支持 `{input}`、`{output}` 占位符，不经过 shell。

### API 模式

已有 OCR 服务时，在设置中选择对应协议并填写地址、认证与超时：

| 服务 | 配置方式 |
| --- | --- |
| MinerU 4 V1 | `ocr.mode=mineru_v1`，填写服务根地址；应用处理上传、轮询和结果下载 |
| MinerU 旧版 FastAPI | `ocr.mode=http`、`protocol=legacy_file_parse`，填写 `/file_parse` 地址 |
| 通用 OCR 服务 | `ocr.mode=http`、`protocol=generic`，multipart 上传，返回 markdown/text |
| DS / 兼容评分服务 | 配置 `grading.base_url`、`model`、`wire_api`、独立 API Key、输入/输出限制与超时 |
| GPT / 兼容评分服务 | 配置 `gpt.base_url`、`model`、`wire_api=responses`、独立 API Key；可配置 `reasoning_effort` |
| Blackboard | 配置课程 URL、连接模式、超时与高级端点；REST 模式需相应授权 |

高级 JSON 可配置 OCR 额外表单参数、认证请求头以及评分 API 的 `extra_body`。凭据使用专用输入框，不放进高级 JSON。

## 评分规则与重复处理

评分标准按作业保存。教师提供满分、评分规则和参考答案，应用将它们与结构化输出约束组成 system prompt；学生答案不作为教师指令执行。

- **增量 OCR**：默认复用原件哈希和配置一致的分类、OCR 和页面缓存。需要重做时勾选“本次重新识别已有结果”。升级前的 OCR 结果在能验证原件哈希时也会复用。
- **每次重新评分**：点击“GPT 评分”或“DS 评分”会使用当前规则重新计算该模型的建议分，复用识别缓存，适合修改 prompt 后重试。
- **保护审核结果**：已审核记录须先撤销审核，才能重新 OCR 或评分；已上传及上传待核验记录不会被批次覆盖。
- **最新尝试优先**：同一学生多次提交时，只显示并处理最新尝试，旧记录保留在本地。

对于“错一个小问仍给满分”这样的规则，可以启用“按错题数计分”，选择大题或小问，设置免扣题数与每题扣分。模型只给出错题与依据，程序按公式计算基础分。例如满分 10、免扣 1、每题扣 0.5：错 0–1 个小问得 10 分，错 2 个得 9.5 分。迟交等额外调整在人工审核时完成。

## 附件与上传行为

支持 PDF、常见图片、DOCX、UTF-8 TXT/Markdown，以及包含受支持文件的 ZIP。DOCX 处理正文、表格、Word 原生公式和内嵌图片；可验证的旧版 Equation Editor/MathType 公式优先解析为 LaTeX，必要时 OCR 本地预览。未知嵌入内容或无法完整识别的文档会报错，可导出为 PDF 后重试。

附件失败或内容过长时，不会静默漏读、截断或补零分。模型仍可能误判，需人工核对原文与识别结果。

上传仅针对最新提交的人工审核结果，保留空评语。写入前校验不通过时显示“未发送成绩”，审核结果保留；发送后超时、回读失败或不一致时标记“上传待核验”并停止批次。先到 BB 核对，再通过“上传异常人工核验”记录结果，程序不会自动重复写入。

当前重点适配 USTC Blackboard Original 的个人作业。其他学校或 BB 版本、分组作业、匿名评分等可能需要额外适配。

## 数据存储

源码版默认使用项目 `data/`；打包版默认使用 `%LOCALAPPDATA%/BBMarkAssistant`；演示模式使用独立的 `demo/` 子目录。数据库保存名单、处理结果、审核状态和上传审计，附件、OCR 输出与报告保存在同一数据目录。支持导出 CSV 和 JSON。

本地 OCR 在本机处理附件；使用 OCR API 时会向配置的服务发送附件。自动类型判别会发送页面预览；评分 API 接收规则、参考答案及分流后的正文或原图。GPT 与 DS 分别发送到各自配置的服务；协作评分还会向 GPT 发送 DS 的判断，并向 DS 发送 GPT 的复核意见。学生数据、设置、凭据、模型及本地诊断文件均不属于公开仓库内容。

## 开发与打包

首次运行 `run.ps1` 创建应用环境后：

```powershell
uv pip install --python .appvenv/Scripts/python.exe -e '.[dev]'
.\.appvenv\Scripts\python.exe -m pytest -q
.\.appvenv\Scripts\python.exe -m ruff check src tests scripts
.\build.ps1
```

输出为 `dist/BBMarkAssistant/BBMarkAssistant.exe`。分发时保留整个 `BBMarkAssistant` 目录，不要只复制 exe。OCR 模型需另行安装或使用 API。

本地构建依赖已经安装时，可用 `.\build.ps1 -SkipDependencyInstall` 离线打包，避免包下载服务超时影响构建。

测试使用合成数据和模拟接口，不需要真实账号或 API Key，也不会向 BB 写入成绩。
